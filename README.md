# فضاء الثانوية | School Hub — الإصدار 1.3

تطبيق ويب تقدمي بثلاث لغات (العربية، الفرنسية، الإنجليزية) لإعلانات المؤسسة وأخبارها وأنديتها وأنشطتها ومعرض الوسائط، مع نظام لتخطيط المشاريع الثقافية وتتبع التنفيذ والمؤشرات.

## تشغيله على Windows

1. حمّل ملف ZIP وفك الضغط عليه باستعمال **Extract All / Extraire tout**.
2. افتح `index.html` للتجربة الأساسية.
3. لاختبار المزامنة من GitHub والتثبيت كـ PWA، استضف الملفات عبر HTTPS. يمكن أيضاً تشغيل خادم محلي بالأمر `python -m http.server 8000` داخل مجلد التطبيق ثم فتح `http://localhost:8000`.

## وحدات تدبير المشاريع

1. افتح **المشاريع الثقافية** وأنشئ بطاقة المشروع: رمز، مجال، أهداف، فئة مستهدفة، مستفيدون متوقعون، مسؤولون، تواريخ، عدد الأنشطة، شركاء، موارد ومؤشرات نجاح.
2. بعد كل نشاط، من **تتبع الأنشطة والمؤشرات** أضف بطاقة الإنجاز: المشاركون المتوقعون والفعليون، حالة التنفيذ، تحقق الهدف، مستوى مشاركة المتعلمين، ارتباط التعلم، الثقافة المحلية، الجمالية والقيم، الموارد، الأدلة والصعوبات والخطوة المقبلة.
3. قيّم النشاط عبر 9 مؤشرات من 0 إلى 4؛ المجموع من 36. التفسير: 0–11 يحتاج إعادة تصميم، 12–23 إنجاز محدود، 24–32 جيد، 33–36 قوي وقابل للتعميم.
4. لوحة التتبع تعرض نسب التنفيذ والمشاركة والتوثيق والتقويم والاستدامة، وتبرز الأنشطة التي تحتاج متابعة.
5. اختر الشهر والمشروع ثم نزّل التقرير بصيغة CSV أو Word، أو افتح الطباعة واحفظه PDF.

## نشر الموقع وتحديث المحتوى عبر GitHub Pages

1. أنشئ مستودعاً جديداً في GitHub وارفع **محتويات المجلد**: `index.html`, `app.js`, `styles.css`, `manifest.json`, `sw.js`, `content.json` ومجلد `assets`.
2. افتح **Settings → Pages**، واختر **Deploy from a branch** ثم الفرع `main` والمجلد `/(root)` واضغط **Save**. يتطلب GitHub Free مستودعاً عاماً لتفعيل Pages؛ لذلك لا ترفع بيانات شخصية أو داخلية للمستودع. راجع دليل GitHub Pages الرسمي قبل النشر: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site
3. بعد ظهور رابط الموقع، افتحه. ملف `content.json` المجاور للتطبيق يُقرأ تلقائياً عند فتح الموقع، ويمكن ضبط رابط آخر من لوحة التدبير.
4. لتحديث الأخبار والأندية والأنشطة والصور: أضف المحتوى من لوحة التدبير، نزّل `content.json`، ثم استبدل الملف القديم في المستودع واعتمد التغيير **Commit**.
5. أضف الصور بروابط عامة مناسبة، والفيديو برابط مشاهدة. لا ترفع صور متعلمين دون الموافقات اللازمة.

## ما الذي يدخل إلى ملف GitHub العام؟

الأخبار، الأندية، الأنشطة، الوسائط، وحقول تعريف مختارة للمشاريع. لا يضم ملف المحتوى العام أسماء التلاميذ أو طلبات الانخراط أو سجلات بطاقات الأنشطة الداخلية أو ملاحظاتها. راجع أي `content.json` قبل نشره.

## تفعيل البيانات المشتركة

رابط Supabase ومفتاح Publishable مضافان في `backend-config.js`. شغّل `supabase-schema.sql` في SQL Editor، أنشئ مستخدم إدارة ثم أضف UUID ديالو إلى `user_roles` حسب الشرح المفصل في `SUPABASE-SETUP.md`. من بعد ارفع النسخة إلى GitHub Pages. التلميذ يرسل الطلب للقاعدة، والإدارة تدخل بالبريد وكلمة المرور لمراجعته. لا تضع مفتاح `secret` أو `service_role` في ملفات الواجهة.

## حدود النسخة الحالية

عند تشغيل إعداد Supabase وسياسات SQL، تتشارك طلبات الأندية والأنشطة وسجلات المشاريع بين الأجهزة، ويتطلب التدبير دخول الإدارة. إذا لم تُشغّل SQL أو لم يعمل اتصال Supabase، يبقى التطبيق في وضع العرض المحلي. اختبر ببيانات وهمية أولاً، واحفظ نسخة احتياطية دورية. للاستعمال الرسمي المشترك نحتاج إلى خادم وقاعدة بيانات بصلاحيات دخول، ونقل التقارير الداخلية إلى مساحة خاصة.
